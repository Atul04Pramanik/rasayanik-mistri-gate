## Verdict on the idea

- [Likely] The differentiator is the Hinglish explanations in the Ayon/Drishti/Host_RM voices, plus your channel as free distribution. The dice is a cheap, fun wrapper around that.
- [Likely] The GATE app market is crowded with free question banks. You won't win on features, only on explanation quality and community.
- [Certain] Your schema is MCQ-only. GATE Chemical also has MSQ and NAT questions, with different marking (MCQ has negative marks; MSQ and NAT don't). I've fixed this in the schema below.

## Where I disagree

**1. User-uploaded PDFs.** I disagree because users uploading PDFs means copyrighted coaching and publisher material flows through your app, and LLM extraction on messy scans produces wrong answer keys. Here's what I'd do instead: make ingestion admin-only. You upload PDFs, run the pipeline below, review, and then publish. The risk in your approach is a takedown on your channel's name and a wrong key teaching students the wrong answer.

**2. Glide + Google Sheets.** I disagree because Sheets has API rate limits and no real-time behaviour [Likely]. Leaderboards and duels will lag or break past a few dozen concurrent users. Here's what I'd do instead: FlutterFlow + Firebase only. The risk in Glide is a rebuild right when you get traction. [Certain] Cloud Functions need Firebase's Blaze (pay-as-you-go) plan, so a billing account is required, though costs at this scale are usually tiny [Likely].

**3. Scheduled push notifications on a PWA.** [Likely] Web push is the weakest part of the PWA route in FlutterFlow. On iPhones it only works after the user installs the app to the home screen. Plan on WhatsApp/Telegram reminders from your channel as a fallback, and don't build your retention on push.

Cloud Functions to write: `onAttemptCreate` updates user stats, topicStats, the daily doc, and group member scores. `joinGroup(code)`, `createDuel`, and a scheduled notification sender complete the set.

**Leaderboard score** (consistency + accuracy, so grinders don't just win on volume):
`weeklyScore = correct × 10 + activeDays × 20 + accuracyPct × 0.5`

## 2. Dice Roll logic

```
function rollDice(user, filters):
    pool = questions WHERE status == "published"
           AND matches(filters)
           AND NOT attempted by user in last 7 days (unless pool < 20)

    // 20% pure randomness keeps it a dice, not a tutor
    if random() < 0.20:
        return uniformPick(pool)

    for q in pool:
        t = user.topicStats[q.topic]
        // Bayesian smoothing: new topics aren't instantly "weak" or "strong"
        acc = (t.correct + 2.5) / (t.attempted + 5)
        weakness = 1 - acc                          // 0..1

        targetDiff = clamp(round(1 + acc * 4), 1, 5)  // better acc -> harder
        diffFit = 1 - abs(q.difficulty - targetDiff) / 4

        wasWrongBefore = lastAttempt(user, q) is wrong
        reviewBoost = 1.5 if wasWrongBefore AND daysSince >= 3 else 1.0
        unseenBoost = 1.2 if never attempted else 1.0

        q.weight = (0.3 + 1.7 * weakness) * (0.5 + diffFit)
                   * reviewBoost * unseenBoost

    // anti-streak guard: no topic > 40% of last 10 rolls
    for q in pool:
        if share(last10Rolls, q.topic) > 0.40: q.weight *= 0.3

    return weightedPick(pool, q.weight)   // roulette-wheel on cumulative sum
```

**Dice face.** Pick the question first, then animate. The face is cosmetic, but you can make it a mechanic: a 6 means "Weakness Distillation round" (forces your lowest-accuracy topic) with 2× Catalyst Points. Players get to feel the dice matters.

## 3. PDF → JSON system prompt

I'd run this in two passes: extract, then independently verify.

```
You are a GATE Chemical Engineering question-extraction engine for the
"Rasayanik Mistri" platform. Convert the raw PDF text below into a JSON array.
Output ONLY valid JSON. No markdown, no commentary.

SCHEMA per question:
{ "type": "MCQ|MSQ|NAT", "question": str (equations in LaTeX),
  "options": [{"id":"A","text":str}], "correct_answer": ["B"] | {"min":n,"max":n} | null,
  "marks": 1|2, "topic": str, "subtopic": str, "difficulty": 1-5,
  "has_diagram": bool, "needs_review": bool, "review_reason": str|null,
  "explanation_hinglish": {"speaker":"ayon|drishti|host_rm","text":str,"trap":str} }

HARD RULES
1. NEVER invent correct_answer. Use only the answer key present in the text.
   If missing or ambiguous: correct_answer=null, needs_review=true.
2. If a question depends on a figure/graph/table you cannot see:
   has_diagram=true, needs_review=true. Do not guess its content.
3. If text is garbled (OCR errors in numbers/units), needs_review=true and
   quote the broken part in review_reason. Never "fix" numerical data silently.
4. topic must be one of: [Engineering Maths, Process Calculations,
   Thermodynamics, Fluid Mechanics, Mechanical Operations, Heat Transfer,
   Mass Transfer, CRE, Instrumentation & Process Control,
   Plant Design & Economics, Chemical Technology, General Aptitude].
5. difficulty: 1 = direct formula/definition, 3 = 2-step application,
   5 = multi-concept numerical.

HINGLISH EXPLANATION RULES
- Roman-script Hindi + English technical terms. Never translate terms like
  "Reynolds number", "azeotrope", "enthalpy".
- Speaker: ayon = concept/theory questions (curious, "arre dekho, yahan
  physics yeh hai"); drishti = numericals and plant-practice questions
  (grounded, "plant mein aisa hota hai"); host_rm = exam-strategy/trap questions.
- Structure: (1) correct answer in one line, (2) why it is correct, with
  working steps for numericals, (3) "trap": the specific mistake that makes
  the wrong options attractive. Max 120 words.
- If you are not confident in the working, set needs_review=true instead
  of writing a confident-sounding wrong explanation.

Process these pages in batches of 5-10 questions.
INPUT: {{pdf_text_chunk}}
```

**Verification pass:** feed each question without its key to a second call, ask it to solve independently, and flag every mismatch for human review. [Likely] LLMs get a meaningful share of multi-step GATE numericals wrong, so you must manually verify every numerical before publishing. Your channel's credibility rides on this.
